# KNK-1342 게스트 이용 동의

## 승인 범위와 구현

게스트 제작과 채팅을 복원하고 기존 Drawer로 안내 카드와 상세를 표시합니다. 제목은 `시작하기 전에 확인해주세요` 한 줄이며 체크박스 없이 `동의하기` 하나를 사용합니다. 회원 동의와 로그인 수정은 유지합니다. 게스트 동의 서버 API는 이번 범위에 없으며 브라우저 기록만 구현합니다.

1. 게스트 안내 문구, 법적 상세, 버전과 시각 저장 및 동의 대기 로직
2. 제작 생성 요청, 채팅 전송과 재생성, 추천 입력 생성 연결. 제작 진입 동의는 후속 요청으로 제거
3. 게스트 채팅 서재 저장과 서버 체험 한도 처리 복원
4. 약관 전문, 하네스 Spec, Design, QA 동기화
5. 타입 검사, lint, 단위 테스트, 기능 E2E와 라이트 및 다크 화면 검증

## 연동 및 공개 전 확인

- 게스트 로컬 동의는 서버 증빙이 아닙니다. 게스트 동의 API 제공 후 계약에 맞춰 연결합니다.
- 전문은 이용약관 v1.4, 개인정보 처리방침 v1.6, 시행일 2026-09-20 초안입니다. 공개 전 공지와 법률 검토가 필요하며 서버 회원 요구 버전(`MANYAK_LEGAL_*_VERSION`)과 배포 일정을 함께 맞춰야 합니다. 백엔드와 Android 문서 및 환경 변수는 수정하지 않습니다.
- 현재 하네스에는 `planning/client-tracking.md`가 없어 결과와 검증은 이 계획 문서에 기록합니다.
- 기존 앱 프레임과 Drawer를 재사용하며 새 의존성과 게스트 동의용 가상 API는 추가하지 않습니다.

## 검증 결과

- `pnpm typecheck`, `pnpm lint`: 통과
- `pnpm test`: 96개 파일, 632개 테스트 통과
- `pnpm test:e2e --reporter=line`: 322개 통과, 기존 비활성 테스트 9개 건너뜀
- 마지막 시트 초기 초점 보완 후 `e2e/auth/guest-consent.spec.ts`: 7개 통과
- Docker Linux 비주얼: 게스트 안내 및 상세 라이트/다크, 체험 한도 로그인, 약관과 개인정보 처리방침, 서비스 안내의 관련 7개 테스트 통과. 게스트 4개 화면을 추가하고 법적 문서 및 서비스 안내 기준 이미지를 갱신했습니다. 마지막 초점 수정 뒤 게스트 비주얼 2개 테스트도 다시 통과했습니다.
- 동의 전 요청 차단, 동의 후 단일 재개, 브라우저 뒤로가기, 제작 이동, 새로고침과 저장소 삭제, 저장소 쓰기 차단, 별도 브라우저 컨텍스트 재동의, 체험 잔여 0을 API 목킹 E2E로 확인했습니다. 실제 시크릿 창 및 인앱 기기, 운영 서버 연동 검증을 대체하지 않습니다.
- 하네스 Spec, Design, ADR W-012와 QA를 동기화했고 새 상대 링크 및 앵커 30개와 두 저장소의 `git diff --check`를 확인했습니다.
- 새 의존성을 추가하지 않았습니다. 이전 로그인 강제 훅은 사용처를 교체한 뒤 제거했습니다. 커밋, 푸시와 배포는 하지 않았습니다.

## 카드 UI 후속 조정

카드 제목을 16px 볼드로 변경하고 보조 설명의 기존 서체와 색상은 유지한 채 끝 마침표만 제거했습니다. 마지막 카드의 상세 버튼은 "자세히 보기"로 줄여 제목 오른쪽 끝에 배치하고 높이를 24px로 맞췄습니다. 시트 제목, 동의 버튼과 동의 로직은 유지합니다.

타입 검사와 lint, 단위 테스트 632개, 게스트 동의 E2E 7개와 Linux 라이트 및 다크 비주얼 테스트 2개가 통과했습니다. 카드 제목의 실제 글꼴 크기와 굵기, 상세 버튼의 높이와 제목 행 정렬을 검증하고 기준 이미지를 갱신했습니다. 웹 Spec과 QA 문구를 동기화했습니다. 전체 E2E는 앞선 실행 결과이며 이번 스타일 변경 후에는 관련 E2E만 실행했습니다.

## 제작 동의 시점 후속 조정

제작 목록, 초안 재개, 빈 채팅 목록, 공유 CTA, 온보딩과 직접 URL 진입에서 동의 검사를 제거했습니다. 게스트도 먼저 키워드를 입력하고, 입력 검증을 통과한 `스토리라인 만들기` 클릭에서 기존 생성 요청 가드로 동의받습니다. 동의 취소 시 입력과 단계를 유지하고, 동의하면 같은 입력으로 한 번만 요청합니다. 회원 동의와 채팅 동의 시점은 유지합니다.

제작 퍼널 안에서 시트를 닫을 때 이탈 확인창까지 열리는 충돌을 재현해, 시트가 열린 동안 `usePreventPageLeave`의 뒤로가기 처리를 건너뛰도록 수정했습니다. Spec, Design, ADR W-013, 사용자 스토리와 QA를 동기화했습니다.

- 타입 검사와 lint, 단위 테스트 632개 통과
- 전체 기능 E2E 실행: 321개 통과, 9개 건너뜀, 1개 테스트 실패. 실패 원인은 재개한 시트가 열리기 전에 Escape를 보내던 테스트 동기화였으며, 시트 표시를 기다리도록 수정한 뒤 게스트 동의 E2E 7개 모두 통과. 이 테스트 수정 후 전체 스위트는 재실행하지 않음
- Linux 라이트 및 다크 비주얼 2개 테스트 통과. 생성 입력 화면 위 동의 시트 기준 이미지 갱신
- 웹과 하네스 `git diff --check`, 새 상대 링크 및 앵커 33개 확인

## 상세 버튼 밑줄 제거

안내 카드의 "자세히 보기" 버튼에서 밑줄만 제거했습니다. 배치와 높이, 상세 화면의 약관 전문 링크는 유지합니다. 웹 Spec과 QA를 동기화하고 기존 비주얼 테스트에 밑줄 없음 검증을 추가했습니다.

타입 검사, lint, 단위 테스트 632개와 Linux 라이트 및 다크 비주얼 2개 테스트가 통과했습니다. 안내 화면 기준 이미지를 갱신했습니다. 최초 lint는 비주얼 실행 중 `test-results` 디렉터리 정리와 겹쳐 ENOENT로 중단되어 비주얼 종료 후 재실행해 통과했습니다.

## 상세 드로워 높이 조정

상세 화면에만 `calc(100dvh / 3)` 높이를 적용했습니다. 공통 Drawer와 안내 화면 높이는 변경하지 않고 기존 본문 스크롤과 제목 및 동의 버튼 배치를 재사용합니다. 웹 Spec과 QA를 동기화했습니다.

타입 검사, lint, 단위 테스트 632개와 Linux 라이트 및 다크 비주얼 2개 테스트가 통과했습니다. 실제 상세 높이가 화면 높이의 1/3인지, 마지막 전문 링크까지 스크롤해도 제목과 동의 버튼이 보이는지 검증하고 기준 이미지를 갱신했습니다.

후속 요청으로 2/3 높이를 검증한 뒤, 최종 요청에 따라 비율 지정 자체를 제거하고 원래 공통 Drawer 높이로 복원했습니다. 최종 높이는 콘텐츠 기준이며 최대 `calc(100dvh - 6rem)`입니다. Spec과 기준 이미지를 원복된 동작에 맞췄고, 타입 검사와 lint, 단위 테스트 632개, Linux 비주얼 2개 테스트가 통과했습니다. 본문 끝까지 스크롤해도 제목과 동의 버튼이 유지되는 검증은 남겼습니다.

## 안내 화면 간격 조정

안내 화면의 제목과 카드 묶음 사이, 카드 묶음과 동의 버튼 사이는 각각 32px, 카드 사이는 8px로 조정했습니다. 상세 화면 간격과 공통 Drawer는 유지합니다. 웹 Spec과 QA를 동기화했습니다.

타입 검사와 lint, 단위 테스트 632개, Linux 비주얼 2개 테스트가 통과했습니다. 실제 요소 경계로 간격 `[32, 8, 8, 32]`를 검증하고 라이트 및 다크 안내 화면 기준 이미지를 갱신했습니다.

## 분리 커밋 전 최종 검증

최종 코드 기준 전체 E2E를 다시 실행해 322개 통과, 기존 비활성 9개 건너뜀을 확인했습니다. 같은 코드에서 통과한 타입 검사, lint, 단위 테스트 632개와 최종 간격의 Linux 비주얼 2개 결과를 재사용합니다. 동의 공통 UI 및 저장, 제작과 채팅 연결, 약관 및 안내를 웹 커밋으로 나누고 하네스 Spec, Design, ADR과 QA는 별도 문서 커밋으로 기록합니다. 푸시와 배포는 이번 범위에 포함하지 않습니다.

## 게스트 동의 서버 API 연동

사용자가 제공한 생성 API 클라이언트를 `232947b`로 먼저 커밋했습니다. 이 후속 요청은 위의 브라우저 기록 임시 구현을 대체합니다. 기존 Drawer, 동의 시점과 단일 버튼을 유지하고 `useGetConsents1` 및 `useRecordConsents1`로 연동합니다. 매 동작 직전 조회하고 `guestPrivacy.requiredVersion`을 그대로 저장하며, 같은 버전의 `needsConsent: false`를 확인해야 대기 동작을 재개합니다. 로컬 동의 기록을 자동으로 서버에 이전하지 않습니다.

조회 실패와 누락된 응답은 차단하며 재시도를 제공합니다. 저장 실패 시 입력과 시트를 유지하고 중복 제출을 막습니다. 버전 불일치는 최신 상태를 다시 조회해 상세를 표시하며 새로운 명시 동의 전에는 POST하지 않습니다. 취소 및 경로나 인증 변경 뒤의 응답은 원래 요청을 재개하지 않습니다.

기기 식별자는 기존 mutator의 `X-Manyak-Device-Id`를 재사용합니다. production의 Amplitude SDK 및 쿠키 식별자가 없으면 이 API도 400으로 실패할 수 있으며 별도의 식별자를 만들거나 로컬 기록으로 통과시키지 않습니다. 실제 인앱 환경의 SDK 및 쿠키 사용 가능 여부는 별도 검증 대상입니다. 서버 API 계약상 `guestPrivacy`만 기록하며 회원의 세 동의 항목으로 이전하지 않고, 다른 게스트 API 자체를 차단하지 않습니다.

기존 미공개 초안의 브라우저 전용 동의 기록 설명을 서버 저장으로 정정했습니다. 문서 공개 전 법률 검토, 공지 및 시행일과 회원/게스트 서버 요구 버전 정합성 확인은 여전히 필요합니다. 생성 API에는 게스트 동의 기록 보유기간과 문서 본문 공급 계약이 없어 기간을 임의로 새로 쓰지 않았으며, 실제 보유 및 삭제 정책은 서버 담당자 확인이 필요합니다. 백엔드와 Android 소유 문서 및 서버 환경 변수는 수정하지 않았습니다.

검증 결과:

- `pnpm typecheck`, `pnpm lint`: 통과
- `pnpm test`: 96개 파일, 630개 통과. 삭제한 로컬 저장소 테스트 3개를 서버 응답 검증 테스트 1개로 대체
- `pnpm test:e2e --reporter=line`: 328개 통과, 기존 비활성 9개 건너뜀. 게스트 동의 13개 포함
- 최초 대상 E2E의 저장 중 버튼 검증은 로딩 시 접근 가능한 이름이 달라지는 것을 반영하지 않아 실패했고, 로딩 이름으로 단언을 수정한 뒤 위 전체 E2E에서 통과
- Docker Linux 비주얼: 게스트 안내 및 상세 라이트/다크, 체험 한도 로그인, 약관과 개인정보 처리방침 상단의 5개 테스트 통과. 기존 기준 이미지와 같아 이미지 변경 없음
- 웹과 하네스 `git diff --check`, 변경된 문서 상대 링크 및 앵커 7개, QA ID 및 ADR ID 중복 없음 확인
- API 목킹 검증이며 실제 서버 저장, 실제 시크릿 창 및 인앱 기기 검증은 별도로 필요합니다. 푸시와 배포는 하지 않습니다.

## PR 충돌 해결과 최신 dev 통합

웹 `4447c73`과 하네스 `b34c5a6`을 작업 브랜치에 병합했습니다. 최신 Google 팝업 및 Kakao 같은 탭 로그인을 유지하며, 인증 시작 전에 원래 탭에 로그인 진행 표시를 기록해 회원 동의 게이트를 이어갑니다. 신규 핸드오프 생성과 외부 브라우저 직행은 복원하지 않습니다. 게스트 서버 동의와 회원 동의 완료 후 자동 이관, 빈 세션 쿠키 판정과 Secure 쿠키 삭제를 모두 유지합니다.

하네스의 기존 W-014와 W-015는 보존하고 이번 게스트 서버 동의 기록을 W-016으로 정리했습니다. 중복 QA ID는 기존 dev의 AUTH-LOGOUT-06을 보존하고 탭 표시 삭제 케이스를 AUTH-LOGOUT-07로 옮겼습니다. 최신 Android 선택 동의 계약도 보존했습니다. Next.js와 React 지침에 따라 기존 공용 로그인 함수와 동의 게이트를 재사용하며 새 추상화나 의존성을 추가하지 않았습니다.

- 타입 검사, lint 통과
