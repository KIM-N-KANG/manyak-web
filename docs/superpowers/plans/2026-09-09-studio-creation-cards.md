# 웹 제작 카드·다중 완성 요청 전환 계획

- 상태: 기존 하네스 전환안을 이관한 초안. 구현 착수 전 검토 필요.
- 이관: KNK-1236. 기능 구현 티켓·일정은 미배정이며 이 티켓으로 제품 코드를 변경하지 않습니다.
- 현재 동작: [웹 제작 계약](../../../../knk-harness/docs/product-specs/3-2-web-spec.md#웹-제작-흐름). 변경 목표: [공통 계약](../../../../knk-harness/docs/product-specs/3-1-client-spec.md#제작-카드와-다중-완성-진행), [C-004](../../../../knk-harness/docs/product-specs/3-1-client-adr.md#c-004).

## 승인된 변경 목표와 적용 조건

초안 하나와 requestId별 완성 요청을 분리하고 요청 영속 성공 후 제작 탭으로 돌아옵니다. 스토리라인 생성·복구와 편집 자동 저장은 유지합니다. 실패 카드 UX·완료 분석 변경은 [추적 문서](../../../../knk-harness/docs/planning/client-tracking.md#계약-확인-항목)의 제품 확인 후 확정합니다. 그 전에는 잠정 UI를 승인된 계약으로 옮기지 않습니다.

## 변경 순서

1. 편집 슬롯과 requestId별 요청을 분리합니다. 기존 STORY_COMPLETION의 명령·생성 결과·입력·requestId를 PENDING 요청으로 보존 이전합니다. 요청 추가와 해당 초안 제거가 하나의 제출로 처리되는 저장 방법은 착수 직전 확정합니다.
2. 영속 성공 후 `/studio`로 replace하고 셸 수명의 실행자가 POST를 보냅니다. 같은 요청만 합류시키고 서로 다른 요청을 직렬화하지 않습니다. 새로고침·탭 재방문은 복구 조회로 결과를 확인합니다.
3. 초안·요청·서버 스토리를 표시하고 같은 storyId를 중복 표시하지 않습니다. 진입·포커스·새로고침 및 보이는 미확정 카드의 5초 조회를 연결합니다. POST 201은 완료, 네트워크·401/403은 미확정, 나머지는 복구 GET으로 판정합니다. 미접수 요청은 같은 requestId·명령으로 재전송합니다.
4. 웹 게스트의 로그인 유지·로그아웃 정리, 완료 시 로컬 서재 ID를 한 번만 추가하는 부수효과와 storage 이벤트 동기화를 연결합니다. 회원 소유자 격리·게스트 경계는 Android 저장 방식을 그대로 복사하지 않고 확정합니다.

## 검증·복구

초안 1개+완성 중 2개, 저장 실패 미전송, 연타 합류, 오프라인 제출 후 복귀, 완료 카드의 서버 카드 전환, 초안 삭제와 다른 요청 격리, 탭 간 동기화, 로그인·로그아웃을 확인합니다. 기존 레코드 이전 실패 시 원본을 지우지 않으며 해석 실패의 안내·재시도와 구버전 복귀 가능 범위는 저장 방식과 함께 정합니다.

## 완료 시 문서 처리

적용 승인과 검증 결과를 확인한 뒤 웹 스펙의 단일 슬롯 예외를 갱신하고 웹 설계에 실제 저장·실행 구조를 반영합니다. 기술 갈림길의 이유는 웹 ADR에 C-004를 연결해 남깁니다. 이 계획에는 결과·PR·검증 링크를 추가해 완료 기록으로 보관합니다.
